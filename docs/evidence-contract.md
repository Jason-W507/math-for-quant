# 研究材料与复现约定

这份说明承载书稿正文不需要反复出现的项目约定。它定义如何维护学习单元、独立核对结果和出版产物；正文只保留读者需要理解的数学对象、算例和适用边界。

## 学习单元的四项证据

一个学习单元应同时具备：

1. 符号、定义和假设与共享注册一致；
2. 核心结论可以由证明、反例或独立计算复核；
3. Python 实验有手算、解析解、枚举或独立算法作为参照；
4. 口述、推导、编程和研究判断题都有提示、答案与研究连接。

“已验收”是项目维护状态，不是正文中的数学术语。`oracle` 在代码和证据文件中表示独立参照值；面向读者的文字优先写“手算基准”或“解析基准”。

## 三层材料

- 主书保留定义、推导、直觉、算例、研究含义和关键适用范围；
- 实现说明只说明算法选择、误差来源和实验结论；
- notebook、测试和项目文档保存路径、命令、fixture、schema、哈希、标准输出和失败类别。

正文不以文件路径、日志字符串或 CI 输出替代解释。第 17 章可以讨论复现问题，但具体命令和目录仍放在本说明及其链接的实验材料中。

## 证据命名

项目内部可以继续使用学习单元证据包、双轨数据、双实现对照和 Capstone 等名称。它们是组织材料的方便标签，不改变定理、命题和经验诊断之间的逻辑等级。正式发布时由 `tools/build_release.py` 汇总版本、来源、许可证和校验值。
